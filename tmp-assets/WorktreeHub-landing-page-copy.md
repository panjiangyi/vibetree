# WorktreeHub

把多分支开发，整理成一个真正可用的工作台

在一个本地 Web 应用里管理 Git worktree、打开真实终端、保留运行中的会话。少一点反复切分支，少一点窗口混乱，少一点上下文丢失。

## Hero

**为频繁并行开发的人设计的本地 Git worktree + Web Terminal 工作台。**

- 在一个界面里管理多个 Git 项目和 worktree
- 为每个 worktree 打开真实 shell，而不是伪终端

## 你真正卡住的，不是开发本身

一个分支修 Bug，一个分支做新功能，一个分支等 PR review，另一个分支还在跑测试。

传统方式里，你只能在这些动作之间来回切换：

- `git stash`
- 切分支
- 切目录
- 找终端窗口
- 回忆这个命令到底是在哪个 worktree 里跑的

问题不是 Git 不够强，而是你的工作现场太碎了。

## WorktreeHub 做的事很直接

WorktreeHub 把两件原本分散的事情合在一起：

1. 管理 Git worktree
2. 直接进入对应目录的网页终端

它不是把 Git 包一层花哨 UI，而是把多分支开发里最容易混乱的部分整理出来，变成一个可以长期使用的本地工作台。

## 为什么它比“多开几个终端”更有效

### 每个 worktree 都是独立上下文

你可以同时维护多个分支，各自独立，不再互相污染。修线上问题、做新功能、验证 PR，可以并行推进。

### 终端和 worktree 绑定

不是凭记忆去猜哪个窗口对应哪个目录。点开 worktree，就进入那个 worktree 的真实终端。

### 刷新页面，现场还在

浏览器刷新不等于工作中断。终端会话可以恢复，减少重复进入上下文的成本。

### 关掉浏览器，任务继续跑

只要后端还在，终端里的构建、测试、脚本和日志任务就会继续执行。回来以后，状态还在那里。

### 真正适合本地开发

默认本地运行，数据保存在本地 SQLite。它不是重型平台，而是一个贴着开发者日常工作的 Local First 工具。

### 手机也能顺手看一眼

同一局域网下，你可以直接从手机访问。长时间任务在跑的时候，不必总回到电脑前确认进度。
